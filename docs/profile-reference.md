# Profile reference

Generated by bin/lib/gen-profile-doc from schema/profile.schema.json. Do not edit by hand.

| Key | Type | Default | Required | Description |
|---|---|---|---|---|
| `project` | string; pattern `^[a-z0-9][a-z0-9-]*$` | required | yes | Project name, used in run ids, logs and the registry. |
| `prefix` | string; pattern `^[a-z][a-z0-9]{0,9}$` | required | yes | Run-id prefix, for example pf gives run ids like pf-123. |
| `docs` | object | `{}` | no | Pointers to project documents the agents read, as paths relative to the repo. |
| `docs.contributing` | string | none | no | Contributing guide. |
| `docs.dod` | string | none | no | Definition of done; may carry a #anchor. |
| `docs.releasing` | string | none | no | Release procedure. |
| `docs.guidelines` | string | none | no | Coding and testing guidelines. |
| `docs.adr_dir` | string | none | no | Directory where architecture decision records go. |
| `commands` | object | required | yes | Commands run with bash -c in a worktree; they override the stacks' own commands. May be empty. |
| `commands.test` | string | none | no | Test command. |
| `commands.lint` | string | none | no | Lint command. |
| `commands.typecheck` | string | none | no | Type-check command. |
| `commands.audit` | string | none | no | Dependency audit command. |
| `commands.setup` | string | none | no | Setup command run once per worktree; replaces the stacks' setup steps. |
| `git` | object | required | yes | Branch naming and merge conventions. May be empty. |
| `git.base_branch` | string | `"main"` | no | Branch that pull requests target. |
| `git.plan_branch` | string | `"plan/{slug}"` | no | Run branch; holds the ledger. |
| `git.fix_branch` | string | `"fix/{slug}"` | no | Code branch for T0 and T1 runs. |
| `git.feature_branch` | string | `"feature/{n}"` | no | Feature branch for T2 and T3 runs. |
| `git.phase_branch` | string | `"feature/{n}--{phase}"` | no | Phase branch within a feature run. |
| `git.merge` | string; const `--no-ff` | `"--no-ff"` | no | Merge flag used when merging phase branches. |
| `git.phase_trailer` | string; pattern `^[A-Z][A-Za-z-]*$` | `"Plan-Phase"` | no | Commit trailer key naming the plan phase. |
| `git.plan_doc` | string | `"docs/{slug}-plan.md"` | no | Path of the plan document. |
| `worktrees` | string | `"{coding}/worktrees/{repo}-{slug}"` | no | Worktree directory template; ~ and {coding} expand to the coding directory. |
| `stacks` | array of string; pattern `^[a-z][a-z0-9-]*$` or object, at least 1 | required | yes | Stacks the project uses. A plain name covers the whole repo; an object limits the stack to paths. |
| `stacks[].name` | string; pattern `^[a-z][a-z0-9-]*$` | required | yes | Stack name. |
| `stacks[].paths` | array of string | required | yes | Paths or globs the stack covers. |
| `platforms` | object; keys matching `^(linux\|macos\|windows)$` | `{}` | no | Per platform verification: locally or in CI. |
| `platforms.<platform>` | object | none | no | Verification settings for one platform. |
| `platforms.<platform>.verify` | string; one of `local`, `ci` | none | no | Where the platform is verified. |
| `platforms.<platform>.workflows` | array of string | none | no | CI workflow files that verify the platform. |
| `platform_paths` | object; keys matching `^(linux\|macos\|windows)$` | `{}` | no | Globs that mark a change as platform specific. |
| `platform_paths.<platform>` | array of string | none | no | Globs for one platform. |
| `ci` | object | none | no | CI dispatch settings. |
| `ci.dispatch_only_from_main` | boolean | `true` | no | Dispatch CI workflows only from the base branch. |
| `ci.workflows` | object; keys matching `^[A-Za-z0-9._-]+\.ya?ml$` | `{}` | no | Workflows Nightshift may dispatch, keyed by file name. |
| `ci.workflows.<file>` | object | none | no | Settings for one workflow; an empty object is valid. |
| `ci.workflows.<file>.input` | string | none | no | Name of the single workflow_dispatch input to pass. |
| `ci.workflows.<file>.needs_approval` | boolean | `false` | no | Whether dispatching needs a human approval. |
| `risk_zones` | object; keys matching `^[a-z0-9-]+$` | `{}` | no | Named code areas that need extra review, keyed by zone name. |
| `risk_zones.<zone>` | object | none | no | One risk zone. |
| `risk_zones.<zone>.paths` | array of string, at least 1 | required | yes | Globs that make up the zone. |
| `risk_zones.<zone>.require` | array of string | none | no | Agents that must review changes in the zone; may be empty. |
| `protected_paths` | array of string | `[]` | no | Globs the guard hook refuses to edit. |
| `specialists` | array of string; one of `database-expert`, `data-analyst`, `ui-ux-designer` | `[]` | no | Specialist agents to enable (Build B). |
| `domain_skills` | array of string | `[]` | no | Project skills under .claude/skills/<name>/SKILL.md that agents load. |
| `budgets` | object; keys matching `^T[0-3]$` | `{"T0": {"hours": 0.5, "review_rounds": 1}, "T1": {"hours": 2, "review_rounds": 3}, "T2": {"hours": 8, "review_rounds": 3}, "T3": {"hours": 36, "review_rounds": 3}}` | no | Per tier budget overrides; missing tiers take the defaults. |
| `budgets.<tier>` | object | none | no | Budget of one tier. |
| `budgets.<tier>.hours` | number; > 0 | none | no | Wall-clock hours allowed. |
| `budgets.<tier>.review_rounds` | integer; 1..10 | none | no | Review rounds allowed. |
| `agents` | object; keys matching `^(triage\|conductor\|researcher\|product-analyst\|architect\|planner\|test-architect\|implementer\|code-reviewer\|sec-compliance\|integrator)$` | `{}` | no | Per agent overrides, keyed by agent name. |
| `agents.<agent>` | object | none | no | Overrides for one agent. |
| `agents.<agent>.model` | string; one of `haiku`, `sonnet`, `opus`, `fable` | none | no | Model to use. |

## Example

```yaml
project: privacyfence
prefix: pf
docs:                          # pointers the agents read
  contributing: CONTRIBUTING.md
  dod: docs/coding-and-testing-guidelines.md#27-definition-of-done
  releasing: docs/releasing.md
commands:                      # per stack defaults can be overridden here
  test: .venv/bin/pytest -q
  lint: .venv/bin/ruff check .
git:
  base_branch: main            # where PRs go; e2e tests point this at a throwaway branch
  plan_branch: "plan/{slug}"
  feature_branch: "feature/{n}"
  phase_branch: "feature/{n}--{phase}"
  merge: "--no-ff"
  phase_trailer: "Plan-Phase"
  plan_doc: "docs/{slug}-plan.md"
worktrees: "~/Coding/worktrees/{repo}-{slug}"
stacks:
  - { name: python, paths: ["src/", "tests/", "scripts/*.py"] }
platforms:
  linux:   { verify: local }
  macos:   { verify: ci, workflows: [build.yml] }
  windows: { verify: ci, workflows: [build.yml] }
platform_paths:
  macos:   ["**/*macos*"]
  windows: ["installer/**"]
ci:
  dispatch_only_from_main: true
  workflows:
    qa-record-fixture.yml: { input: connector, needs_approval: true }
    build.yml: {}
risk_zones:
  policy: { paths: ["src/**/policy/**"], require: [sec-compliance] }
protected_paths: [".github/workflows/**", "credentials/**"]
specialists: []                # Build B: database-expert, data-analyst, ui-ux-designer
domain_skills: [pf-invariants]
budgets:                       # optional per-project override of section 7 defaults
  T3: { hours: 36 }
```

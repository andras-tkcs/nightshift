Nightshift

A personal agent pipeline that runs while you are at your day job. Everything runs on one Ubuntu server with the full Claude Code CLI. You reach it from your iPad or a browser tab over a private network, steer at the start and the end, and the server does the long middle. A reusable generic plugin does the work, and a thin PrivacyFence pack tells it what matters in this codebase.

3 · Languages and platforms

One project, several languages

The core (agents, tiers, triage, ledger, review desk) knows no language. Each language is a stack plugin, and a project lists every stack it uses with the paths it covers. Separately, it lists the platforms it ships to, because some code can only be built and tested on its own operating system. Places on this page that depend on Python carry the python mark.

PrivacyFence uses five stacks

From GitHub's language statistics for the repo: mostly Python, plus TypeScript and JavaScript, HTML and CSS, shell, PowerShell and an Inno Setup installer script.

How runs use this

  • Skills load by path. A change under installer/ loads the PowerShell stack's skills; a change in src/ loads Python's. A typo fix loads none.
  • Checks run per stack. Each touched stack's lint and tests run in its own paths, so one PR can run pytest, shellcheck and PSScriptAnalyzer.
  • Platforms decide where the proof comes from. Linux code is verified on ns-main. macOS or Windows code is verified only by dispatching that platform's workflow and reading the result, which PrivacyFence's steward rules already require.
  • Triage counts platforms. Touching macOS or Windows code raises the risk floor to at least T1 and adds the dispatch to the plan, because ns-main can't run it.

What every stack plugin must supply

  • Detection rule and default paths
  • Lint, test, type-check and dependency-audit commands
  • Worktree setup (for Python: venv and pip install -e .)
  • Cleanup targets for ns gc (for Python: .venv, pip cache)

The Swift catch: it needs a Mac

  • Xcode, Apple's app frameworks and the iOS simulator run only on macOS. ns-main can edit Swift but can't build or test a Mac or iOS app.
  • Start with GitHub's macOS runners through ci-dispatch, as PrivacyFence already does for its macOS installer. Free on public repos; on private repos macOS minutes count extra.
  • Later, a Mac build worker: a Mac mini at home or a rented one, on your tailnet as a self-hosted runner. Signing secrets live only there.
  • UI tests produce simulator screenshots for the review desk.

Adding a stack later: write the stack plugin, add it to the marketplace, list it in the project's profile, install its server packages as root. Nothing in the core changes.

5 · How triage decides

Size and risk, scored separately

Size signals (generic)

  • Estimated files and modules touched
  • New public surface: tool, setting, CLI flag, UI page
  • Unknowns that need research
  • Cross-platform or packaging impact
  • Docs that must change with it

Risk signals (from the profile)

  • Path matches a declared risk zone
  • Changes an approval, policy or PII decision
  • Touches credentials, auth or the audit trail
  • Alters what data reaches the AI client
  • Changes a compliance claim in docs or website
  • Runs SQL, changes a schema or releases query results → database-expert
  • Defines metrics, datasets or reports → data-analyst
  • Changes a screen, dialog, settings page or the website → ui-ux-designer
  • Touches macOS- or Windows-only code → at least T1, plus that platform's CI dispatch
tier = max( size_tier, risk_floor ) risk_floor: none → T0 · any risk zone → T1 + sec-compliance · invariant at stake → T2 · new trust boundary → T3 you can always override: /ns:run --tier T1 "…"

10 · Operations · generic

Reboots and housekeeping

A reboot never loses a run, because every run's state is in its ledger in git. It can lose the step that was in progress, so drain first when you can. Claude and the runs are started by hand after a reboot, with one command.

Before a planned reboot

ns drain # workers finish their current step, # write a checkpoint and stop ns ls # every run shows "parked" ssh root@ns-main reboot
  • Security updates install on their own, but never reboot on their own. ns-gc pushes "reboot required" to your phone when an update needs one.
  • An unplanned reboot (Hetzner maintenance, a crash) is the same, minus the drain. Each run loses at most its current step.

After the reboot

mosh ns@ns-main ns up # checks services, Claude login, gh, disk; # restarts the Remote Control session ns ls # parked runs ns resume 123 # or: ns resume --all
  • Back on their own: Tailscale, Caddy, cloudflared, SilverBullet, the ns-gc timer.
  • Started by you, on purpose: Claude sessions, Nightshift runs, Remote Control. You see the state before agents spend usage again.
  • A plain interactive session comes back with claude --continue in its folder.

GitHub environment "live-qa"

What keeps a two-day run from going wrong

  • no mainBranch protection on main; agents never merge, tag a release, or run /cut-release.
  • scoped tokenFine-grained GitHub token for this repo only, no admin or workflow-secret rights.
  • no open portsThe server is reachable only inside your tailnet.
  • no live grantsQA tokens stay on the separate runner; dispatched QA jobs wait for your approval.
  • untrusted textIssue bodies, PR comments and web pages are data; agents never follow instructions found in them.
  • budgetsEach tier has a token and wall-clock cap; hitting it stops and escalates.
  • loop capThree review rounds per phase, then a human decides.
  • split rolesReviewers are read-only and never see the implementer's reasoning.
  • tests firstAcceptance tests are written before code and cannot be weakened to pass.
  • ledgerEvery step is checkpointed, so a reboot resumes instead of restarting.
  • no live dataThe runner never holds connector credentials; live QA stays on your self-hosted runner.

15 · GitHub settings script

ns-gh: audit, then apply

One script checks a repo against Nightshift's defaults and fixes only what differs. audit changes nothing and exits non-zero when something differs; apply shows the same table, asks, then changes the differences. Per-project values come from .claude/ns-github.env on the default branch, read as data and never executed.

What it checks

  • Default branch, allowed merge types, delete branch on merge
  • A ruleset on the default branch: no deletion, no force push, PR required with 0 approvals (you can't approve your own PRs), required checks
  • Secret scanning and push protection, private vulnerability reporting (public repos)
  • Dependabot alerts and security updates
  • Actions: read-only default token, workflows can't approve PRs, artifact retention
  • Nightshift labels: ns:queued, ns:running, ns:needs-you, ns:done, tier:T0–T3
  • Environments, such as live-qa with you as reviewer

How to run it

#!/usr/bin/env bash
# ns-gh: audit or apply Nightshift's GitHub repository settings.
#
#   ns-gh audit owner/repo          show wanted vs current, change nothing
#   ns-gh apply owner/repo [--yes]  audit, ask, then fix only what differs
#
# Run it as root on ns-main with an admin token for the repo's owner in GH_TOKEN
# (fine-grained, 7-day expiry, Administration + Environments + Issues: write;
# one token per owner, because a fine-grained token covers a single owner).
# The agents' tokens under the ns user deliberately can't do this.
#
# Per-project overrides: .claude/ns-github.env on the repo's default branch,
# KEY=value lines for the keys listed under "Defaults". Read as data, never executed.
set -euo pipefail

MODE=${1:-}; REPO=${2:-}; FLAG=${3:-}
if [[ $MODE != audit && $MODE != apply ]] || [[ $REPO != */* ]]; then
  echo "usage: ns-gh audit|apply owner/repo [--yes]" >&2; exit 2
fi
command -v gh >/dev/null && command -v jq >/dev/null || { echo "needs gh and jq" >&2; exit 2; }

# ---------- Defaults (override per project in .claude/ns-github.env)
DEFAULT_BRANCH=main
REQUIRED_CHECKS=""                 # comma-separated status check names, e.g. "pytest,ruff"
ALLOW_MERGE_COMMIT=true
ALLOW_SQUASH_MERGE=true
ALLOW_REBASE_MERGE=false
DELETE_BRANCH_ON_MERGE=true
WORKFLOW_PERMISSIONS="read"        # default GITHUB_TOKEN permission: read | write
ARTIFACT_RETENTION_DAYS=14
ENVIRONMENTS=""                    # comma-separated name:mode, mode = reviewer | main-only
LABELS="ns:queued=0e8a16,ns:running=1d76db,ns:needs-you=d93f0b,ns:done=5319e7,tier:T0=c5def5,tier:T1=c5def5,tier:T2=bfd4f2,tier:T3=bfd4f2"
RULESET_NAME="ns-default-branch"

KNOWN="DEFAULT_BRANCH REQUIRED_CHECKS ALLOW_MERGE_COMMIT ALLOW_SQUASH_MERGE ALLOW_REBASE_MERGE DELETE_BRANCH_ON_MERGE WORKFLOW_PERMISSIONS ARTIFACT_RETENTION_DAYS ENVIRONMENTS LABELS"
if overrides=$(gh api "repos/$REPO/contents/.claude/ns-github.env" -H "Accept: application/vnd.github.raw" 2>/dev/null); then
  while IFS= read -r line; do
    [[ $line =~ ^([A-Z_]+)=(.*)$ ]] || continue
    key=${BASH_REMATCH[1]}; val=${BASH_REMATCH[2]}
    val=${val%\"}; val=${val#\"}
    [[ " $KNOWN " == *" $key "* ]] || { echo "ignoring unknown key $key" >&2; continue; }
    [[ $val =~ ^[A-Za-z0-9_.,:=/\ -]*$ ]] || { echo "ignoring $key: unexpected characters" >&2; continue; }
    printf -v "$key" '%s' "$val"
  done <<<"$overrides"
  echo "using overrides from .claude/ns-github.env"
fi

# ---------- Output helpers
DIFFS=()
row() {  # row <setting> <want> <have>
  local status="ok"
  if [[ $2 != "$3" ]]; then status="DIFF"; DIFFS+=("$1"); fi
  printf '%-34s %-28s %-28s %s\n' "$1" "$2" "$3" "$status"
}
info() { printf '%-34s %s\n' "$1" "$2"; }

api_or() {  # api_or <fallback> <gh api args...>: body on success, fallback on any error
  local fb=$1 out; shift
  if out=$(gh api "$@" 2>/dev/null); then printf '%s\n' "$out"; else printf '%s\n' "$fb"; fi
}

ME=$(gh api user --jq .login)
ME_ID=$(gh api user --jq .id)
R=$(gh api "repos/$REPO")
VISIBILITY=$(jq -r .visibility <<<"$R")

echo
echo "Repository $REPO ($VISIBILITY) · admin: $ME · mode: $MODE"
printf '%-34s %-28s %-28s %s\n' SETTING WANT HAVE STATUS
printf '%.0s-' {1..100}; echo

# ---------- 1. Repository settings
row default_branch          "$DEFAULT_BRANCH"         "$(jq -r .default_branch <<<"$R")"
row allow_merge_commit      "$ALLOW_MERGE_COMMIT"     "$(jq -r .allow_merge_commit <<<"$R")"
row allow_squash_merge      "$ALLOW_SQUASH_MERGE"     "$(jq -r .allow_squash_merge <<<"$R")"
row allow_rebase_merge      "$ALLOW_REBASE_MERGE"     "$(jq -r .allow_rebase_merge <<<"$R")"
row delete_branch_on_merge  "$DELETE_BRANCH_ON_MERGE" "$(jq -r .delete_branch_on_merge <<<"$R")"

# ---------- 2. Security
if [[ $VISIBILITY == public ]]; then
  row secret_scanning                 enabled "$(jq -r '.security_and_analysis.secret_scanning.status // "unknown"' <<<"$R")"
  row secret_scanning_push_protection enabled "$(jq -r '.security_and_analysis.secret_scanning_push_protection.status // "unknown"' <<<"$R")"
  row private_vulnerability_reporting true "$(api_or '{"enabled":"unknown"}' "repos/$REPO/private-vulnerability-reporting" | jq -r .enabled)"
else
  info secret_scanning "n/a on private repos without GitHub Secret Protection"
fi
if gh api "repos/$REPO/vulnerability-alerts" >/dev/null 2>&1; then VA=true; else VA=false; fi
row dependabot_alerts            true "$VA"
row dependabot_security_updates  true "$(api_or '{"enabled":false}' "repos/$REPO/automated-security-fixes" | jq -r .enabled)"

# ---------- 3. Actions
WP=$(api_or '{}' "repos/$REPO/actions/permissions/workflow")
row workflow_token_permissions   "$WORKFLOW_PERMISSIONS" "$(jq -r '.default_workflow_permissions // "unknown"' <<<"$WP")"
row workflows_can_approve_prs    false                   "$(jq -r '.can_approve_pull_request_reviews // "unknown"' <<<"$WP")"
AR=$(api_or '{}' "repos/$REPO/actions/permissions/artifact-and-log-retention")
if [[ $(jq -r '.days // empty' <<<"$AR") ]]; then
  row artifact_retention_days "$ARTIFACT_RETENTION_DAYS" "$(jq -r .days <<<"$AR")"
else
  info artifact_retention_days "not readable via API here; check Settings → Actions → General"
fi

# ---------- 4. Ruleset on the default branch
RS_ID=$(api_or '[]' "repos/$REPO/rulesets" | jq -r --arg n "$RULESET_NAME" '.[] | select(.name==$n) | .id' | head -1)
WANT_RULES="deletion,non_fast_forward,pull_request"
[[ -n $REQUIRED_CHECKS ]] && WANT_RULES+=",required_status_checks"
if [[ -n $RS_ID ]]; then
  RS=$(gh api "repos/$REPO/rulesets/$RS_ID")
  HAVE_RULES=$(jq -r '[.rules[].type] | sort | join(",")' <<<"$RS")
  HAVE_CHECKS=$(jq -r '[.rules[] | select(.type=="required_status_checks") | .parameters.required_status_checks[].context] | sort | join(",")' <<<"$RS")
  row ruleset_enforcement "active" "$(jq -r .enforcement <<<"$RS")"
else
  HAVE_RULES="(no ruleset)"; HAVE_CHECKS=""
fi
row ruleset_rules    "$(tr ',' '\n' <<<"$WANT_RULES" | sort | paste -sd, -)" "$HAVE_RULES"
row required_checks  "$(tr ',' '\n' <<<"$REQUIRED_CHECKS" | sed '/^$/d' | sort | paste -sd, -)" "$HAVE_CHECKS"

# ---------- 5. Labels
HAVE_LABELS=$(gh label list -R "$REPO" --limit 200 --json name,color --jq '.[] | "\(.name)=\(.color)"' | sort)
IFS=',' read -ra WANT_LABEL_LIST <<<"$LABELS"
for l in "${WANT_LABEL_LIST[@]}"; do
  name=${l%%=*}
  have=$(grep -E "^${name//./\\.}=" <<<"$HAVE_LABELS" | head -1 || true)
  row "label $name" "$l" "${have:-(missing)}"
done

# ---------- 6. Environments
IFS=',' read -ra ENV_LIST <<<"$ENVIRONMENTS"
for e in "${ENV_LIST[@]}"; do
  [[ -z $e ]] && continue
  name=${e%%:*}; mode=${e#*:}
  EJ=$(api_or '' "repos/$REPO/environments/$name")
  if [[ -z $EJ ]]; then row "environment $name" "$mode" "(missing)"; continue; fi
  case $mode in
    reviewer)  have=$(jq -r --argjson me "$ME_ID" 'if ([.protection_rules[]? | select(.type=="required_reviewers") | .reviewers[]?.reviewer.id] | index($me)) then "reviewer" else "no reviewer" end' <<<"$EJ");;
    main-only) have=$(jq -r 'if .deployment_branch_policy.custom_branch_policies == true then "main-only" else "any branch" end' <<<"$EJ");;
    *) have="unknown mode";;
  esac
  row "environment $name" "$mode" "$have"
done

echo
if [[ ${#DIFFS[@]} -eq 0 ]]; then echo "All settings match."; exit 0; fi
echo "${#DIFFS[@]} setting(s) differ."
[[ $MODE == audit ]] && exit 1

if [[ $FLAG != --yes ]]; then
  read -r -p "Apply these changes to $REPO? [y/N] " ans
  [[ $ans == y || $ans == Y ]] || { echo "Nothing changed."; exit 1; }
fi

has() { local d; for d in "${DIFFS[@]}"; do [[ $d == "$1"* ]] && return 0; done; return 1; }
step() { echo "→ $*"; }

# ---------- Apply
if has default_branch || has allow_ || has delete_branch; then
  step "repository merge settings"
  gh api -X PATCH "repos/$REPO" \
    -f default_branch="$DEFAULT_BRANCH" \
    -F allow_merge_commit="$ALLOW_MERGE_COMMIT" -F allow_squash_merge="$ALLOW_SQUASH_MERGE" \
    -F allow_rebase_merge="$ALLOW_REBASE_MERGE" -F delete_branch_on_merge="$DELETE_BRANCH_ON_MERGE" >/dev/null
fi
if has secret_scanning; then
  step "secret scanning and push protection"
  jq -n '{security_and_analysis:{secret_scanning:{status:"enabled"},secret_scanning_push_protection:{status:"enabled"}}}' \
    | gh api -X PATCH "repos/$REPO" --input - >/dev/null
fi
if has private_vulnerability_reporting; then step "private vulnerability reporting"; gh api -X PUT "repos/$REPO/private-vulnerability-reporting" >/dev/null; fi
if has dependabot_alerts;  then step "Dependabot alerts";           gh api -X PUT "repos/$REPO/vulnerability-alerts" >/dev/null; fi
if has dependabot_security; then step "Dependabot security updates"; gh api -X PUT "repos/$REPO/automated-security-fixes" >/dev/null; fi
if has workflow_token || has workflows_can_approve; then
  step "Actions token permissions"
  gh api -X PUT "repos/$REPO/actions/permissions/workflow" \
    -f default_workflow_permissions="$WORKFLOW_PERMISSIONS" -F can_approve_pull_request_reviews=false >/dev/null
fi
if has artifact_retention; then
  step "artifact retention"
  gh api -X PUT "repos/$REPO/actions/permissions/artifact-and-log-retention" -F days="$ARTIFACT_RETENTION_DAYS" >/dev/null \
    || echo "   could not set; change it in Settings → Actions → General"
fi
if has ruleset || has required_checks; then
  step "ruleset $RULESET_NAME on the default branch"
  BODY=$(jq -n --arg name "$RULESET_NAME" --arg checks "$REQUIRED_CHECKS" '
    {name:$name, target:"branch", enforcement:"active",
     conditions:{ref_name:{include:["~DEFAULT_BRANCH"], exclude:[]}},
     rules: ([{type:"deletion"},{type:"non_fast_forward"},
              {type:"pull_request", parameters:{required_approving_review_count:0,
                 dismiss_stale_reviews_on_push:false, require_code_owner_review:false,
                 require_last_push_approval:false, required_review_thread_resolution:false}}]
             + (if $checks == "" then [] else
                 [{type:"required_status_checks", parameters:{strict_required_status_checks_policy:false,
                   required_status_checks: ($checks | split(",") | map({context:.}))}}] end))}')
  if [[ -n $RS_ID ]]; then
    gh api -X PUT "repos/$REPO/rulesets/$RS_ID" --input - <<<"$BODY" >/dev/null
  else
    gh api -X POST "repos/$REPO/rulesets" --input - <<<"$BODY" >/dev/null
  fi
fi
for l in "${WANT_LABEL_LIST[@]}"; do
  name=${l%%=*}; color=${l#*=}
  if has "label $name"; then step "label $name"; gh label create "$name" --color "$color" --force -R "$REPO" >/dev/null; fi
done
for e in "${ENV_LIST[@]}"; do
  [[ -z $e ]] && continue
  name=${e%%:*}; mode=${e#*:}
  has "environment $name" || continue
  step "environment $name ($mode)"
  case $mode in
    reviewer)
      jq -n --argjson id "$ME_ID" '{reviewers:[{type:"User", id:$id}], deployment_branch_policy:null}' \
        | gh api -X PUT "repos/$REPO/environments/$name" --input - >/dev/null;;
    main-only)
      jq -n '{deployment_branch_policy:{protected_branches:false, custom_branch_policies:true}}' \

      gh api -X POST "repos/$REPO/environments/$name/deployment-branch-policies" -f name="$DEFAULT_BRANCH" -f type=branch >/dev/null 2>&1 || true;;

done

P · Easy to forget

Things not covered above

Backup and restore

  • In git, safe anywhere: code, plans, ADRs, approved desk documents, run ledgers.
  • Only on ns-main: ~/.claude (login, transcripts), ~/.config/ns (tokens, project list), ~/sb-data and /srv/ns-space (desk drafts not yet approved).
  • Hetzner's daily backups cover those. If the server is lost: new server, phase 2, bootstrap.sh, re-enter the tokens; runs resume from their ledgers in git.

Someone gets a token

  • GitHub agent token: revoke it under Developer settings; branch protection kept it away from main; check recent pushes.
  • Claude login: /logout on ns-main, then sign out other sessions on claude.ai.
  • Tailscale: remove the machine in the admin console. Cloudflare: Networking → Tunnels → ns-main → refresh the token (or delete the tunnel and create a new one), then rerun bootstrap.sh.
  • docs/security.md keeps this list next to the threat model.

Knowing the server is down

  • ntfy messages come from ns-main itself, so a dead server sends nothing.
  • Add a free dead-man's switch such as healthchecks.io: ns gc pings it daily, and a missed ping emails you.

Where your data goes

  • Code and conversations go to Anthropic for the model; transcripts are deleted from ns-main after 30 days.
  • Cloudflare decrypts traffic to the desk: fine for PrivacyFence, which is public; use the Tailscale addresses for private projects.
  • No employer or client code on this server; check your employer's policy before using it from the work laptop.

Versions of Nightshift

  • Tag releases in the nightshift repo and keep a CHANGELOG.md.
  • The installed plugin follows a tag, not main, so a half-finished Build B never breaks a running run.

Shutting it down

  • Delete the servers and lab snapshots, revoke the tokens, delete the tunnel and the Access apps, remove the machines from Tailscale.
  • docs/operations.md has the checklist.
